digital_twin/README.md and _read_until_close()'s comment still called the
unsized read the live path for GET /, read from Microdot's 1 KB
send_file_buffer_size chunks. The code says otherwise:
_StaticRoutes.serve() (src/asy_webserver_service.py) opens the frozen
file itself, sets Content-Length from the stream's size and the
response's send_file_buffer_size to chunk_bytes (256 B on every device,
the generated modules' chunk_bytes=256); Microdot's Response.complete()
adds the header for every bytes body and _pieces_response() for the
streamed JSON routes. So every response carries Content-Length and
fetch() reads GET / through _read_exact() (_drain_exact() with
read_body=False); the unsized _read_until_close()/_drain_until_close()
pair is the fallback for a body EOF ends. The README now says that, and
that the whole-body allocation is _read_exact()'s buffer or the join.
