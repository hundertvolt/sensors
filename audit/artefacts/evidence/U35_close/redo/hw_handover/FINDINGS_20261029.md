# Bench campaign, 2026-10-29: what was added, what it found, what the triage left

The raw output of every run is in `HANDBACK.md` (day 20261029). This file is the reading of it and the record of the
session's decisions (agent, 2026-10-29, at the owner's request: "measure as many values and situations as possible which
might be valuable for the planned audit steps"; "There are many open hardware questions in the repo. I want to find as
many answers as possible reasonably with the current state."; "Save all the details, push, and then do run what you held
back.").

## Changes to the campaign (agent, 2026-10-29)

- The runner runs in a separate worktree (`../sensors-bench`, branch `claude/u35-bench-campaign`), so the shared main
  checkout keeps its branch. The Pi's global uv is 0.12.6 against the 0.8.17 pin; the worktree uses a pinned uv in
  `.uvpin/bin` (untracked). `uv self update 0.8.17` fixes the main checkout.
- `long_i2c.py`'s SGP40 idle and `long_net.py`'s reconnect outlasted every 540 s slice (600 s, 900 s), so neither was
  ever measured; now 120 s then every 180 s, and every 240 s (commit eaa1f4c2, from 2026-10-29 ~13:00 UTC).
- `extras.sh` holds one-off steps (`STEPS="..."`); a step whose script arms the watchdog runs last, since rp2 cannot stop
  it (listener_close's watchdog reset the board 8 s into the next script).
- Day 1's `i2c_timing.py` aborted with ETIMEDOUT on the measure after the SGP40's unknown command, so its SCD30 timeout
  sweep and general call never ran on day 1 (found by the triage); the step now retries up to 10 s, rerun as `i2c_rerun`.

The triage's risks, kept: never run `scd30_start_continuous_measurement`, `scd30_argument_reaction`,
`scd30_same_device_rw_concurrency` or `bus_concurrency_scd30_write_vs_siblings` (a bare 0x0010 is the NVM-backed start
command); never `flash_write_loop_gap`, `config_float_round_trip`, `reboot_persist_write`,
`system_debug_level_set_standard`, `config_files_restore` (flash writes); avoid scripts calling
`FRAMManager.get_chunk()` (they overwrite production's first FRAM chunk); under `mpremote mount` relative paths land on
the host, absolute ones on flash; mounted modules go as `.mpy` (`build/mountstage/mpy`, staged by
`build_firmware.stage_python_modules()` for `dev` and compiled by the pinned mpy-cross) so the heap need not compile
them. Results from project modules hold only where R1 leaves the code unchanged (B6's UART code nearly so; B3/B4 not).
