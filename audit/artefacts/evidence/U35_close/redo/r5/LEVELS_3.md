## Findings, ranked (leaner form that loses nothing)
1. **Boot stagger waits on a one-shot that can be dropped** (S; audit 10-07; C). `start_timers()` waits each slot on a preallocated ONE_SHOT `Timer` + flag (`asy_system_service.py:200-201,738-745`), yet U10 (41b47f1d) moved the stagger into task context, where its own fallback `asyncio.sleep_ms(wait)` (`:742-743`) gives the same t0 + k·slot with the same loop latency. The Timer adds one cost, which the twin pins: a dropped soft fire (8-deep queue, F.1) stalls BOOT_TIMERS until the watchdog (`scripts/_digital_twin_scenarios.py:1831-1845`). The "watchdog is the backstop" ruling (owner, 2026-07-18) dates from the original callback-chain `_timer_sequencer` (8c4a73d5), so its premise is gone. Leaner: `await asyncio.sleep_ms(wait)` alone, the shape the storage auto-unpause already took (C.9). Removed: timer, flag, arm `try`, `--test-drop-timer-fire sequencer` and its scenario, the fake-timer stepping in 5 test files (these then read the triggers' arm instants; up to 1 s real wait per test boot).
2. **Two FRAM couplings DESIGN_FU's sweep did not list** (U; pre-audit / audit 10-22; C code, I effect). (a) `wifi_mode_lock` is held across NTP's FRAM-backed `err_s` (`asy_ntp_client.py:402-403`, which reaches `:226,232,256,342`) and across 14 of WiFi's own (`asy_wifi_service.py:344,360,448,451,611-637,697,700,810,823`). So the uptime snapshot and a reconnect wait on the FRAM chip, and C.8's ≈9.1 s bound (SPEC :4064-4072) leaves those writes out. After B(ii) each is ~0.15 s: a doc term, no code. (b) A refused or reclaimed connection closes only after its FRAM trace (`asy_webserver_service.py:858,902-908`). That trace is "what paces a refused client" (agent 10-22, owner-accepted, SPEC :1312-1319). So the pacing is FRAM latency: 0.25-1.1 s loaded today, ~0.15 s after B, none while `mempause` holds. Meanwhile each refused socket keeps its PCB. Owner question: close first, then trace.
3. **Counting loops left after elapsed time became measured** (M/S; loops original, made redundant by U10 10-07; C). NTP's `_sync_age_loop` (`asy_ntp_client.py:385-392`; timer `:185`, flag `:182`, starters `:411,414`) builds a new namedtuple every second only to republish `LastSyncAge`. The notification `_pause_loop` (`asy_notification_service.py:265-276`) only flips `_auto_active` from `_pause.read()`. Both counted in legacy (`async_connect.py:63-71`, `neopixel_signal.py:194-204`) and since `TickSeconds` no longer need to. Leaner: `get_data()` fills `LastSyncAge` from `_sync_age.read()` (the 10 s `_refresh_loop` already reads it inside the 6.2-day horizon), and the monitor tests `_pause.read() == 0` itself (one pass per 3600 s at most). Removed: 2 supervised tasks, 1 of the three unstaggered 1 Hz soft callbacks, `notify.loop_tick_s`; −326 B and −203 B bytecode (methods only). `LastSyncAge` becomes exact instead of up to 1 s stale.
4. **Locks with no await to guard** (F/M; `_data_lock` original, `Locked*` audit 10-07; C). Every `_data_lock` hold is await-free (`asy_base_classes.py:471,541,672`; `asy_scd30_driver.py:508`), yet each `async with` makes three generators (`extmod/asyncio/lock.py:30-56`, v1.29.0) on every `get_data()` and sample store. U10 dropped the locks of `LockedCounter/Flag/Value` (`:235-296`) for exactly that reason but kept the methods async "for a uniform call shape", while `HourlyWindowCounter`/`TickSeconds` beside them are plain: two shapes for one job (D.10). `LockedFlag` has no product user. Leaner: read and assign `_datastruct` plainly; make the four users (`bmp3xx:173`, `isl29125:257`, `system:205`, `webserver:552`) hold plain attributes; delete the classes (703 B bytecode, `LockedFlag` 169 B of it).
