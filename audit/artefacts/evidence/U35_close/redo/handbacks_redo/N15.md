### digital_twin/README.md, "`unixport/_unix_port_udp_addr_shim.py`": replace the last paragraph ("A server's wildcard bind ... binds beside it.") with these two

A server's wildcard bind (`asy_captive_dns.py`'s `("0.0.0.0", 53)`) is bound on the host loopback, where every twin
interface lives (the device's "all interfaces"), at the process's own address: the shim's `twin_host`, read from
`TEST_TWIN_HOST` when the patch is applied and `127.0.0.1` when it is unset; any value but an IPv4 literal in
`127.0.0.0/8` fails the patch, naming the variable. The host's wildcard would also claim the host's other interfaces.
Linux also refuses it beside a socket that holds one specific address on the port without `SO_REUSEADDR`: some CI
runners carry a `dns-resolver` on `127.0.0.100:53`, on which the twin's captive DNS never bound (`DNSSRV` E10). The
twin's address shares none with it. `tests/test_asy_udp_socket.py` holds such a socket and binds beside it.

**One address per process, because the port is the real one.** `asy_udp_socket.py` sets `SO_REUSEADDR`, so two
processes booting a captive DNS on one address share its port 53, and Linux hands each unicast datagram to the socket
bound last: one process's query burst lands in another's listener (the idle-rate test counted 36 wake-ups for 30, the
excess exactly one sibling job's six-query burst), and a test asserting that its own listener answered can be answered
by another's. `scripts/test.sh` gives each running file job an address of `127.0.0.101`-`127.0.0.254` (clear of
`127.0.0.1` and of the resolvers on `.11`, `.53`, `.54` and `.100`) that no running job holds; a job waits while all
are held, and a caller's own `TEST_TWIN_HOST` is unset first. An in-process peer of the twin's own server
(`_dns_burst` in `tests/test_digital_twin_sensortask_integration.py`, the two wildcard tests of
`tests/test_asy_udp_socket.py`) reads `twin_host` instead of naming an address. Everything else sets none, so its twin
binds `127.0.0.1` as before and the host-side talkers (`run_digital_twin_ci.sh`'s Run 7, the scenario harness, the
`tests_scripts/` twins, the live-tier twins) reach it there; inside `scripts/test.sh` the scenario jobs and the
`tests_scripts/` twins still share `127.0.0.1:53`, which nothing there queries (the DNS scenarios are deselected under
`--shared-port-53`). `tests_scripts/test_twin_host_isolation.py` runs two processes on one port and pins the delivery;
`tests_scripts/test_test_sh.py` pins the runner's half.
