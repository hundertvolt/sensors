U35: UART: the docs name the overrun bit's real lifetime and the reversed sender cap

- UARTRSR: FE and BE belong to the byte the DMA read last, while OE stays set until UARTECR is written (RP2040
  datasheet Table 427), so an overrun fails the frame wherever it fell; changelog A13, SPECIFICATION.md C.3.2 and
  the driver's comment said every bit was the last byte's.
- With the sender's own cap check gone, SPECIFICATION.md J.8 and `_over_cap()`'s comment no longer say the sender
  refuses: the receiver's cap is the one refusal, and an `exp_size` past the answer's train fails as a size
  mismatch, still before any allocation.
- Changelog B95: two calls no product path makes, `write()` of nothing and an over-cap SET or GET, send what they
  sent before B48 and B65; a conforming exchange's bytes are unchanged. B95 and B96 are the lead's reversals.

Comments and docs only; no bytecode change.
