# BMP3xx proof run 2 against the real module (comparison unit, read only, 2026-11-05)
B = `S/p10/bmp3xx/tree` at `139eec9` (baseline `33e85ec`). R = `S/wt-r4a` code as checked out (`59d91860`), SPECIFICATION.md at `6e006a95`. `drv` = `src/asy_bmp3xx_driver.py`; PL = a line of `S/p10/bmp3xx/proclog.md`. Method: greps and git reads only, nothing run.

## 1. KEY checks 1-12
1. **Driver shape: matched.** Both have two layers and no interrupt pin (B drv:112,324; R drv:145,419), a 1 s Timer with the inherited `_trigger_loop` divider (B :135-141,291-299; R :169-174,333-342), `@limits address in {0x76, 0x77}` (B :109; R :139), and the one `ADDRESS_CAPABLE_DRIVERS` member (buildspec B :64, R :63). The differences: (a) B declares `_BMP3XX_ADDR = const(0x77)` (:41), the default buildgen reads when a TOML has no `address`. (b) B has no `trigger_s` (R :150,140). R's `_apply_stored_config()` overwrites trigger_s with SampleInterval at init anyway, so B's form is the lower-complexity one. (c) B's protocol class has 9 methods in a 458-line file; R's has 20 in 652 lines. R keeps Adafruit's `get_pressure()`/`get_temperature()`/`get_pressure_altitude()` and a get/set pair per field.
2. **Config schema: matched.** The eight `_VAL_*` tuples equal the KEY's. The only difference is that B writes SampleInterval's bounds as literals (B :71-79; R :93-104). Both put the discrete sets in the sixth slot. Both push the interval and the three chip fields, read back the three chip fields live, and keep the four floats persist-only (B :142-149; R :177-186). Both answer a GET with one snapshot (B :389-398, one 4-byte burst 0x1C-0x1F; R :568-583, three `get_bits()` under one lock). B's getters reuse that snapshot (`_settings_field`, :264-266); R adds 3 reader and 3 protocol getters (R :365-384,585-617). B does not re-check a stored SampleInterval: it has no `set_trigger_s()`/BAD_ARG (R :410-416) and relies on the schema.
3. **Readings: matched, with one difference.** Both have the fields `Pres`/`Temp`/`SLPres`/`TS`. Both subtract the offsets before deriving (B :220-225; R :303-312), treat the range gate as a failed read (B :354-355; R :509-510), and publish an out-of-domain sample without SLPres plus a warning (B :223-224; R :307-309). The helpers differ but give the same formula: B's `math_helpers.sea_level_pressure(p, h, T)` uses US Std Atm 1976 (0.0341632 K/m, |h| <= 11 km), and R's `pressure_at_height(p0, -dh, T)` uses 0.0341626 with |dh| <= 9 km; they agree within 2e-5 relative. **The difference:** when the maths inputs cannot be read, B publishes nothing and adds no error streak (B :206-209), while R measures with `_COMP_FALLBACK` (0, 0, 0, 15) (R :88,245-250). R is better here. The shared CFG_READ text that both log says "it runs on its fallback" (error_catalog.json:49). Under B, a config store that stays unreadable means the module never publishes again.
4. **`@web` tags: the groups, labels, units and specials match; two differences** (B :84-103; R :109-129). (a) B spells the oversampling labels `x1`..`x32`. The brief says ×1..×32, so R matches it (cause: S+B, PL10). (b) B gives every reading and float field a `decimals` (Pres/Temp/SLPres 2, TS 0). R gives none, although brief item 9 requires a precision for every emitted value, so B is better. B's descriptions are its own and longer.
5. **Compensation: matched.** Both use the section 9 formulas with Bosch's float coefficients (B :340-356,365-387; R :474-511,523-545), read the 21-byte trim block and refuse a block of all 0x00 or 0xFF (B :368; R :521). B also refuses T1 = 0 or T2 = 0 (:371). B reads STATUS and the data in one 7-byte burst from 0x03 (:424); R polls STATUS and then reads 6 bytes from 0x04 (:464-468). R derives from Adafruit, with the SPDX header at :1-3 and a THIRD_PARTY_LICENSES entry. B was written from the datasheet: it has no SPDX header and correctly adds no licence entry.
6. **Bounded waits: they differ, but both are bounded; recovery matched.** R polls `cmd_rdy` for up to 50 ms before the reset, settles 2 ms and checks ERR_REG `cmd_err` (:631-643). It polls the conversion every 2 ms for up to 300 ms (:554-566), with three `@tunable` tags (:72-77) and Part N rows (SPEC:11963-11965). B writes the reset at once, waits 2 ms (tstartup) and then reads STATUS once, which must show `cmd_rdy` (:447-458). For a conversion it sleeps once for 1.2x the section 3.9.2 time at the chip's OSR, then reads one burst, which must show drdy (:358-362,413-429). B has no `@tunable` tags and no Part N `bmp3xx.*` rows, although 1.2 is a chosen margin (run 1's K4). B's bound is the plainer one from the datasheet and needs no loop. R's polling tolerates a slow part better. Recovery is the same in both: a soft reset, then the stored config, under `_set_lock` (B :253-262; R :288-297).
7. **Error catalog: differs.** B's band is `W [[71, 71]]` and R's is `[[71, 72]]` (both json:18). B raises E10/11/12/13/26/27 and its own W71 `BMP_OFFSET_RANGE` (drv:33-39, json:161). R raises E10/11/12/13/21/26 and the shared W11 `DERIVED_DOMAIN` (drv:38-44, json:121). B made its own W71 only because the strip took W11, whose only site was this module (S). B logs a range rejection as the shared READ_RANGE 27, whose text names exactly this case and which SCD30 also uses (R scd30:89,479). R logs it as READ 11, so B is better here.
8. **Build-chain rows: matched, with two differences.** Matched: `bus` required and bus kind i2c (buildspec B :16,57); `_build_args_bmp3xx` (codegen B :517,576; R :498,578); the errcount and CFGMGR rows (definitions B :129,147; R :128,146); dev `[bus.i2c0]` 13/12/50 kHz with 0x77 and `fram_target` (B dev.toml:25,112; R :24,96); wozi on `i2c1` with 0x77 and `fram_target` (B :68; R :67). The differences: B's optional fields are `("address",)` alone (B :33), and its pyproject row is `["N801"]` where R has `["FBT001", "N801"]` plus `allowed-confusables = ["×"]` (R pyproject:63-66, which the strip took). B also extended `validate.py` (`_default_address`) and `twin_wiring.py`, so an omitted address becomes the driver's const and is checked for collisions (PL26).
9. **Twin: mostly matched.** B's chip model is 187 lines against R's 207. Both return raw ADC values from the inverted compensation (B uses Newton's method for pressure), use a synthetic trim block, model the soft reset, the POR event and the power cycle, and add the `machine.py` dispatch, `launch.py`'s fault-op entries and the 8 CI-suite tables. B also adds a `stuck_status` hook. **Missing in B:** `launch.py`'s `_read_bmp3xx`/`_forward_bmp3xx` reader (R :176-187,260) and `scripts/_digital_twin_scenarios.py`'s two rows (R :74,100). B never ran the twin CI, which is the run that would have surfaced them.
10. **Tests: far fewer in B.** Unit: 34 against 129. Twin: 11 against 25. math_helpers: +7 against 10. Bus hazard: B adds a generated-catalog adapter flagged `releases_bus_mid_read`; R has an adapter plus 5 mock tests and 4 twin tests written by hand. tests_scripts: B covers generate (+4, including two instances colliding at the default address), definitions, web_tag, limits, registry, wiring and error-contract. B lacks R's validate (12), twin_wiring (2), schema_ast, source_agreement, config_schemas and device_tomls tests. Shared tests B did not restore: setter integration (3), ticks rollover (1, which B needs no longer because it has no polling loop), NTP/FRAM system (1), clock jump, hot replug, and machine (10). Hardware: only the reader in `bus_reader_loops.py`; none of R's 4 device scripts or the flash/bench tests. JS: none.
11. **Docs: largely done.** B wrote M.4 (owner list, chip facts, open decisions) where R has its own M.4. B also wrote the C.7.1 row (B SPEC:3779), C.9.1, I.2, L.3, E.6.6, the twin README fidelity rows and DEVICE_REFERENCE. Part N gains only the `module.max_error` site; the three `bmp3xx.*` rows are missing (item 6). B correctly adds no THIRD_PARTY_LICENSES entry (item 5).
12. **Image size: B is 2,112 B smaller.** B's module costs 71,048 - 62,580 = **8,468 B** of the dev image; R's costs 10,580 B (KEY). Most of the difference is R's extra protocol API and its reader wrappers (item 1).
