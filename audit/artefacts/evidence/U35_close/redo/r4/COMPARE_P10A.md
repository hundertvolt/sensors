## 1. KEY checks 1-11
1. **Driver shape: matched, with two differences.** Both have two layers, `ISL29125_I2C` and `ISL29125_Reader(SensorReaderConfig)` (B drv:500,146; R drv:1124,220), take `irq_pin` positionally and `irq_pull_up` as a keyword (B :150-152; R :224-227), declare `_ISL29125_ADDR = const(0x44)`, which puts the driver in FIXED_ADDRESS_DRIVERS with no TOML `address` (B :37; R :51), and use a 1 s Timer with the inherited `_trigger_loop` divider, arming the INT falling edge inside `start_timer` (B :448-459; R :935-952). The differences: (a) `irq_pull_up` defaults to off in B and on in R. R is better here: INT is open drain (p6), so under B's default a board without its own resistor leaves the line floating. On dev both set it false. (b) B's protocol layer has 4 methods: one 14-byte block read of 0x01-0x0E per cycle, compared with the register image and rewritten. R's has about 30 (a data burst plus a status read, and a config snapshot only on GET or after a failed write). B's form is the lower-complexity one, and it checks for divergence on every cycle.
2. **Config schema: the 11 keys match, two types differ.** In both, Calibrate is special-alone and kept out of `get_dict_cfg()`, and RangeAuto is the only bool (B :82-97,469; R :143-164,962). `AutoRangeThresh` and `AutoRangeDwell` are `int` in B (:85-86) but `float` in R. The brief says only "50-95" and "0-300", so this is design freedom. B also puts the meaning-carrying in-range values in the special slot (Dwell 0, FiltCoeff -1.0), as SGP40 does; R leaves that slot None. B writes the bounds as literals; R uses `@tunable` constants.

B sets it only during a run (0 = "no calibration run"). R sets it every cycle (0 only on a fixed range or mid-switch), so R tells the user when Calibrate can work (brief item 7's band). ## 3. The `math.inf` claim
**The claim holds.** Checked in `S/tc-int/micropython` (v1.29.0):
- mpy-cross enables `MICROPY_COMP_MODULE_CONST` (mpy-cross/mpconfigport.h:57). So `math.inf` (`math` is in the constants table, py/parse.c:662) folds to a float constant at parse time (py/parse.c:876-900).
- The freezer writes every float as `(mp_float_t)%.16g` (tools/mpy-tool.py:790-798). Python formats infinity as `inf` and NaN as `nan`, so frozen_content.c ends up with the bare token `inf`, which is undeclared under rp2's default REPR_A.
- `math.nan` fails the same way. `float("inf")` is a call, which is never folded.
- R's `src/` contains neither (grep).

**It belongs in Part F as a fact.** Put it in F.1, next to F.1's existing sentence on host-folded float constants (6e006a95:6298-6301, which already cites mpy-tool.py:790-797). B's F.9 row is fine as the workaround's register entry. K6 makes the tier that catches the failure part of the procedure.
