**One shape for every MicroPython-target config object** (`src/`, generated code, `digital_twin/`, `tests/`; D.10;
agent, 2026-09-29): a runtime `collections.namedtuple` (one tuple, no instance dict, immutable, so "fixed" holds), typed
through a same-named `typing.NamedTuple` class under `TYPE_CHECKING` (new shared primitive: `if TYPE_CHECKING: class
X(NamedTuple): …` / `else: X = namedtuple("X", (...))`, MicroPython's `namedtuple` having no defaults and no `_replace`,
`py/objnamedtuple.c` v1.29.0), with its defaults as module `const()`s; generated code always passes every field, so a
built object is complete in one step. Host code (`buildgen/`, `scripts/`, `tests_scripts/`) uses a frozen dataclass as
`buildgen/` already does. P6: each new type costs a heap type object at import; the boot-placement bound
(`tests_scripts/test_digital_twin_boot_contiguity.py`) and `tests/test_asy_fram_allocation_budget.py` must still pass,
and the boot heap delta is recorded in the A-C entry. `SettingsGroup` (`asy_webserver_service.py:220-231`) stays as it
is (a per-route group, four fields).
