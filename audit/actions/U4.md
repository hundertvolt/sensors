### A.U4.01 Add the shared `compare_before_write()` primitive
- **Why**: G5/R40 — "A setter goes through the one shared primitive — validate, compare with the store's current value,
  answer "Valid"/"Unchanged", write only what changed — whose store is the config file (current = cache) or a chip
  (SCD30: current = a fresh snapshot per PUT)" (OR42.c (1)); G3/R36 — "compare with a fresh store snapshot at store
  resolution".
- **Site**: `src/config_manager.py`, new module-level function after `check_cfg_get_default()` (`:190-208`).
- **Change**: `compare_before_write(data: dict[str, CfgValue], cfg_vals: ConfigSchema, current: dict[str, CfgValue],
  *, always: tuple[str, ...] = (), resolution: dict[str, Callable[[Any], CfgValue]] | None = None) ->
  tuple[dict[str, CfgValue], WriteValidity]` — synchronous, allocation-light, logs nothing; returns `None` when `data`
  is not a dict (the module's "documented invalid sentinel", header `:3`) and otherwise never raises except
  `MemoryError`. The caller maps `None` to its own whole-call failure: ConfigManager logs 21 BAD_ARG and returns
  `(False, {})` (A.U2.07's `AttributeError` half moves here); SCD30 returns `(False, {})`. Per key of
  `data`, in `data`'s order: not in `cfg_vals` → "Invalid"; `type_or_range_error()` error → "Invalid"; key in `always`
  → coerced value into `write`, "Valid" (a command or action: never compared, never "Unchanged"); key absent from
  `current` → "Failed"; else compare `res(coerced)` with `res(current[key])` (`res` = `resolution[key]`, identity if
  absent): different → `write[key] = coerced`, "Valid"; equal → "Unchanged". Returns `(write, results)`; the caller
  performs the writes and turns a failed write into "Failed". Stores' own concerns stay with the caller: a schema
  default's self-check (ConfigManager) and the application order (SCD30).
- **Blast**: callers A.U4.02 (`ConfigManager.write_config()`), A.U4.04 (`SCD30_Reader._set_mgr_cfg()`) · generated
  — · js the mock compares raw values (`js/mock-server.js:149-155`), so after A.U4.04 it answers "Valid" where the
  product answers "Unchanged" for a TempOffs equal at 0.01 resolution (e.g. 12.345 vs stored 12.35); the
  tick-resolution compare is mirrored in the mock with A.U6.17's rewrite of the same `/sensors` PUT path, or listed as
  a mock gap by U23 (Part G "identical policy in the same change") · tests existing `tests/test_config_manager.py:1813-1823`
  (non-dict → `(False, {})`) holds through the `None` sentinel; `:2529-2540`
  `test_the_only_flash_writes_in_config_manager_are_the_two_known_sites` also pins the new function: no `while `,
  `sleep`, `Timer`, extra `"w"` or `create_task(` in it; new: L1 `tests/test_config_manager.py` — each outcome row
  (unknown key, type error, range error, `always` key, missing current key, equal at resolution, different at
