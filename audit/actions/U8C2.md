## How the classification was done

Every one of the 931 sites (928 family sites and 3 met in a G10 blind spot) was opened in its source context at HEAD (the enclosing function and where the value is
consumed); whether a sleep is real or patched (`_FastAsyncSleep`, fake `Timer`, `sleep(0)` yield helpers such as
`_settle()`/`_pump()`) was checked per file. C.0.2's order was applied with U8C's readings (a timeout waited out in
full is tuned; a value fed to a fake and never waited is test input; API-domain restatements are not tagged; a fixed
readiness sleep in an `l3.`/`l4.` file is deferred U26; cross-file IDs only for copied code or instruments; values
never change). Readings made where C.0.2 and U8C are silent, applied the same way everywhere:
- **Reading E — tolerances on deterministic quantities.** A tolerance whose checked quantity cannot vary run to run
  (fixed inputs, a fake or a set twin scene, no real clock, no hardware) is not tagged: *fact* when it is a float or
  integer rounding epsilon or covers a rounded published figure, *derived* when it is computed from a stated error or
  quantization, *property* when it separates the right result from a named wrong one. A tolerance on a quantity that
  varies (real clock, real hardware, host load, allocator noise) is tuned. (C.0.2 lists "a tolerance" under tuned, but
  only inside "bounds or paces a wait the code under test runs on the real clock".)
- **Reading Y — yield counts.** A count of `asyncio.sleep(0)` yields (directly or through `_settle()`/`_pump()`) bounds
  scheduling passes, not real time: test input. A count whose loop sleeps for real is a poll/retry bound: tuned.
- **Load volume and stimulus length on real time** (rounds, repetitions, attempts, windows at L2-L4) are tuned, as
  U8C tuned `get_iterations`, `hammer_rounds`, `ap_dwell_s`; in the mock tier (fake bus, yields only) they are test
  input.
- **"property"** is used for a literal that states the property under test itself — "at least one", "more than one
  round", "two occupants" — which bounds no wait and is no margin (like U8C's "output cap", outside N.1's list).
- **G16-G19 sites** (added after the verifications): a `% 2` alternation is a fact (parity); a `max(N, …)` floor of 1 or 2 that states
  the property's own minimum ("at least one tab", "at least two occupants") is a property; a floor, multiplier or count that
  sizes concurrent load beyond that minimum is load volume (tuned at L2-L4, test input in the mock tier), unless a stated
  invariant keeps it from ever binding (derived: `max(12, ceiling * 3)` under `assert ceiling >= 4`); a WDT feed cadence or feed step is tuned, a Dependant of `wdt.timeout_ms`; a count restating another
  literal of the case (`max_connections=3`, a 32-byte region, ten deciles) is derived; a `- 1`/`+ 1` index adjustment
  (n − 1 adjacent pairs, an inclusive range end) is a fact.
- **Positional poll bounds** (`for _ in range(N)` × a tuned step) get their own `_…_poll_tries` ID paired with U8C's
  step ID; the product of the two is the wait's deadline.
