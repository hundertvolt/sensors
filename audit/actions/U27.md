- **Why**: G4/R36 — "the firmware build strips them and their import guard (every form: compound tests, `if/else`)

- **Site**: `scripts/_strip_type_checking.py:1-79` (whole module).
- **Change**: verified defect at HEAD: `visit_If()` leaves a compound test (`if TYPE_CHECKING and x:`) or an `if/else`
  in place (`:53`), while `visit_Try()` removes the defining import guard whenever it matches (`:59-62`), so such a
  module would raise `NameError` on import on the board; no `src/` module has such a form today (AST scan of every
  `src/*.py`, all 26 tests are the bare name). New mechanism (agent, 2026-09-30, for the OR2.c review): a line-based
  edit of the original text driven by the AST, never `ast.unparse` — (a) a bare `if TYPE_CHECKING:` /
  `if <mod>.TYPE_CHECKING:` with no `elif`/`else`: every line of the statement (`lineno`…`end_lineno`) becomes an empty
  line; if it was the only statement of its suite, its first line becomes `pass` at the statement's indentation; (b)
  every other load of the name (`Name` or `Attribute` `TYPE_CHECKING` — compound tests, `if/else`, `not TYPE_CHECKING`,
  any expression) is replaced in place by `False`, its runtime value on the board, using the node's `col_offset`/
  `end_col_offset` on its line; MicroPython's compiler emits nothing for an `if False:` suite (v1.29.0
  `py/compile.c:1325-1326`), so the dead branch costs no bytecode and the live one compiles unchanged; (c) the import
  guard (`_is_type_checking_import_guard()`, unchanged) is blanked the same way, and only then; (d) the output is
  re-parsed and must contain no load of `TYPE_CHECKING`, else `StripError(f"{path}:{line}: TYPE_CHECKING still read
  after stripping")` — a new `StripError(Exception)` (the build chain's error contract, A.U27.29). Output keeps every
  line of the input at its line number (comments included; `mpy-cross` drops comments), so a field traceback's line
  numbers equal `src/`'s; with no `ast.unparse` the result depends only on the source text and the AST positions,
  which do not vary with the host CPython or its hash seed. A file with no match is returned unchanged (identity, as
  `:74-75`). Module docstring → "Blanks `TYPE_CHECKING` blocks and their import guard in a staged copy, line for line
