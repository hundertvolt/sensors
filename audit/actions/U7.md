### A.U7.02 Define the runner summary block and its two emitters
- **Why**: G8/R38 — "every runner … ends with the same final block" (OR15.a (2) "(owner, 2026-09-25)"); G2/R27 counts; G1/R18 recovery passes; LEAD/R03 retried passes; OR21.a (3) "a test that passes with nothing actually checked is reported as such".

- **Change**: E.10 defines the block, printed last on stdout, nothing after it:
  ```
  == Summary: <runner> ==
  Commit: <git rev-parse --short HEAD>[ (uncommitted changes)]
  Levels: <L0 PASS · L1 PASS · …>          (only a runner spanning levels; else "Levels: <Ln>")
  GC stage: <-1 (reactive default) | 32768 | both>   (only a MicroPython-running runner)
  Counts (<unit>): passed P · failed F · skipped S · deselected D · retried R · recovered V · vacuous Z
  Failed: <one "  - name: reason" line each, or "none">
  Skipped: <"  - name: reason" each, or "none">
  Deselected: <"  - name: by <runner selection | wear gate --flag>" each, or "none">
  Passed only on retry: <"  - name (attempt k/n)" each, or "none">
  Recovery passes: <"  - name: note" each, or "none">
  Checked nothing: <"  - name" each, or "none">
  Result: PASS | FAIL | NOT CLEAN (<reason>)
  Exit code: <n>
  ```
  Rules: `<unit>` names what is counted (files, tests, checks, runs); retried and recovered passes are counted apart from `passed`, never inside it; a missing or empty per-item verdict counts as failed ("no verdict"); `vacuous` counts items that ran and checked nothing and makes the result FAIL; `Exit code:` equals the process's real exit status; `NOT CLEAN` exits 4 (distinct from 1 = failed and 3 = test.sh's coverage-render-only, SPEC E.5.3), so no caller can read a partial run as clean; a usage error exits 2 in every runner (E.10 lists today's divergent sites: `test.sh:34, :47, :53` exit 1 — changing those is flagged to the lead, not silently done, CLAUDE.md scan rule). `scripts/_summary_block.sh` provides `summary_add <kind> <name> [<detail>]` (kind ∈ passed/failed/skipped/deselected/retried/recovered/vacuous), `summary_levels <text>`, and `summary_print <runner> <exit>`; `scripts/_summary_block.py` provides the same as `Summary` (dataclass with `add()`, `print(exit_code)`) plus `from_run_record(path)` for A.U7.08/A.U7.14. Both print byte-identical layouts; one test proves it (Blast).
