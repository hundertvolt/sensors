## Open points
1. **Blank FRAM block read: skip the busy marker, or mark and restore?** Today a read of a blank block writes BUSY to
   both status bytes and never restores them, so the second read reports "invalid" (STOR.S01). Every fix changes the
   blank-read wire trace, which your account of 2026-09-18 describes ("a copy is marked busy before it is written or
   read and idle after"; blank `setup()` 74 CS cycles).
   (a) Skip the marker on a blank block — nothing is read from a blank block, so there is nothing to protect; 20 fewer
   CS cycles and 4 fewer status writes per blank `setup()` (74 → 54). Recommended.
   (b) Mark busy, then write the blank value back — follows "busy before, restored after" literally; 20 more CS cycles
   (74 → 94) and 4 more writes to the busiest cells.
   Settles A.U16.09 (written for (a)).

**Lead, 2026-09-29: Q1 self-resolved as "skip"** (OR51.a (3)), subject to the U16 verifier's check: a blank-block read writes nothing, so the busy marker has nothing to protect on that path; skipping it (74 → 54 CS cycles) is an implementation choice, not an owner one. Listed for the OR2.c review.
