### A.U19.07 Guard the request head in the stream proxy; refuse quietly
- **Why**: G6/R52 — "Every byte a client sends is bounded before it is allocated: a negative, huge, non-numeric or
  duplicate `Content-Length` is refused outside `ext/` before Microdot's `readexactly()`; header line length and
  count, query string and JSON depth are bounded or proven harmless …; chunked bodies and `Expect: 100-continue` are
  answered cleanly"; State "code+test in U19 (adversarial-client matrix)" (owner, 2026-09-26, OR52.a (3)); G4/R39 "every
  client-controllable size (HTTP headers and bodies …) is bounded before allocation" (seeds REST.S01, REST.S02); G4/R44
  "code in U19 — negative `Content-Length` guarded before `readexactly`"; D4.219 (client-triggered console output,
  G6/R52 State).
- **Site**: `src/asy_webserver_service.py:234-291` `_TimeoutStreamProxy` (`readline()` `:262-263`, `readexactly()`
  `:265-266`), `:54-62` `_StreamLike`; `:692-708` `_serve()` (one proxy of the pair reads).
- **Change**: facts at the pin: Microdot parses `Content-Length` with `int(value)` and reads the body when
  `content_length and content_length <= Request.max_body_length` (`ext/microdot.py:420-426`), so `-1` calls
  `readexactly(-1)`; asyncio's `readexactly()` loops `while n:` (`mp/extmod/asyncio/stream.py:41-51`), the first
  `read(-1)` reads everything available and the next `read(n)` with `n < -1` is let through "and they will cause a
  MemoryError" (`mp/py/stream.c:123-128`). A header or request line grows in asyncio's `readline()` by `l += l2`
  until `\n` (`stream.py:55-64`); Microdot checks `max_readline` only after the whole line is in memory
  (`ext/microdot.py:533-537`), and the header count is unbounded (`:412-421`). Every other malformed head (a request
  line not of three tokens, a header without `:`, a non-numeric length, undecodable bytes) raises inside
  `Request.create()`, which Microdot catches and reports with `print_exception()` (`:1407-1408`) before answering 400.
  The proxy (reader side) becomes the head's bounded parser front:
  (1) `readline()` no longer calls the stream's `readline()`: it keeps `self._rbuf` (bytes) and fills it through
  `self._stream.read(k)` with `k = limit + 1 - len(self._rbuf)`, `limit = Request.max_readline` (Microdot's own class
  attribute, 2048, `ext/microdot.py:317`, read at call time so a pin move carries it), each read through
  `_bounded_read()` as today; it returns up to and including the first `\n`, or the partial buffer at EOF (today's
  `Stream.readline()` behaviour). `readexactly(n)` first takes from `self._rbuf`, then reads the rest from the stream.
  (2) Per connection it counts head lines; the first is the request line, then headers until the blank line. It
  refuses (3) when: a line exceeds `limit`; more than `_MAX_HEADER_LINES` headers arrive (new `const(32)`, tag
