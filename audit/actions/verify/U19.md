- V.U19.Q0 | lwIP queue-length check (lead's addition) | NOTE (why sizing was not chosen; one residual for U21) |
  Verified from source, not from the lead's model: the per-pcb queue check fails a write with room left
  (`tcp_out.c:336-342` returns `ERR_MEM` when `snd_queuelen >= TCP_SND_QUEUELEN`, whatever `snd_buf`; phase 3 `:662-667`);
  ACKs free whole segments only (`tcp_in.c:1110-1127, 1322`); an accepted pcb's cwnd starts at 3,200 B
  (`tcp_in.c:69, 976`), `mss_local` = min(peer MSS ≤ 800, `snd_wnd_max/2`) (`tcp_out.c:420-421`, `tcp_in.c:1959`);
  Nagle holds the last partial segment while data is unacked (`tcp_priv.h:100-105`, `tcp_out.c:1354-1363`) so later
  writes chain onto it and a straddling write costs two pbufs; mid-stream short writes are routine — POLLOUT at any
  `tcp_sndbuf() > 0` (`modlwip.c:1639`), `write_len = MIN(available, len)` (`:792`), and `Stream.write()`/`drain()`
  write the remainder separately (`extmod/asyncio/stream.py:66-88`); JSON pieces are ≤ `chunk_bytes`, not equal
  (`src/asy_webserver_service.py:141-143`). The smallest header block the webserver writes is 104 B (`Connection:
  close` included, `:799`). An independent model (scratchpad `al/vU19/lwsim.py`, `need2.py`) confirms the lead's first
  point — `TCP_OVERSIZE 0` is not equivalent to `TCP_NODELAY`; with Nagle the queue fills with room while writes chain
  — and refutes two: `TCP_NODELAY` at `TCP_SND_QUEUELEN` 8 does stall on the realistic pattern once ACK clocking splits
  pieces (reached in 4-24 % of runs), and QL 10 is not stall-free for it (up to 29 needed when the peer ACKs every
  segment, as Linux quick-ACK does early in a connection); with `TCP_OVERSIZE 0`, 10-13 sufficed in every modelled case.
  So a sizing-only fix needed a larger, peer-dependent queue with no proof for variable piece sizes — the reason to fix
  the loop instead. Residual for U21's override (PR 19705's objection, `SUPP_lwip.md:26-28`): the queue-full-with-room
  state this model shows to be frequent becomes, with `EAGAIN`, a cooperative busy loop — `drain()` yields, POLLOUT is
  reported again at once because `tcp_sndbuf() > 0` (`modlwip.c:1639`), the write returns `EAGAIN` again — until an ACK
  frees a pbuf or the proxy's per-call timeout (5 s, `_TimeoutStreamProxy._bounded()`) reclaims the connection; the
  event loop and watchdog feeding continue. U21's phase-C row should record CPU/latency of other requests while one
  connection sits in that state.
