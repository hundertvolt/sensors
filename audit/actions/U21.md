### A.U21.13 Hammer the patched send path on the lwIP host build
- **Why**: OR115.a (2) — "non-blocking writes against peers that stop reading, many connections at once, the arena,
  segment pool and queue limit driven to their edge — each write returns within a bound, every byte a reading peer is sent
  arrives, memory returns once peers close"; OR115.a lead-in "under the standing gc and memory bars … no VM stall, no WDT
  reset, no `MemoryError` marker, data intact, service recovers" (owner, 2026-09-30, OR115); OR37.a (3) (deterministic,

- **Site**: new `tests/lwip_host/test_modlwip_eagain.py` (microtest runner `tests/microtest.py`); tunables per A.U8.02's
  test-tier grammar.
- **Change**: every test builds its sockets in synchronous test scope and drives them with non-blocking `write()`/
  `recv()`/`accept()` in bounded loops, pumping lwIP with `time.sleep_ms(1)` (which reaches the event hook); no
  `select.poll`, no asyncio stream (CLAUDE.md: a Unix-port poll on a non-fd object can hang on GitHub runners). Setup:

  returns_within_the_bound` — client sockets are opened and accepted until lwIP refuses a new pcb (`socket()` raises

  than copied from `[lwip]`; all but one pair are then used as non-reading peers, each client writing 256 B pieces until `write()` returns `None`/raises `EAGAIN`; every single `write()` is timed with `time.ticks_ms()` and
