## Candidates

### G3.001 CRC algorithm identities are fixed
- **Req**: CRC8 is Sensirion's CRC-8 (poly 0x31, init 0xFF, no reflection, no final XOR), CRC16 is CRC-16/CCITT-FALSE and CRC32 is CRC-32/MPEG-2; these identities never change, since the chips and the UART C peer depend on them. Test vectors come from the datasheets.
- **Class**: product
- **Sources**: ALGO.N001, SENS.N250 · stated at `src/crc_checks.py:1-4`, `tests/test_crc_checks.py:26-41`
- **Provenance**: F — SGP40 datasheet v1.2 Table 7 (dstxt sgp40 lines 469-495: poly 0x31, init 0xFF, example CRC(0xBE 0xEF)=0x92); SCD30 Interface Description lines 167-168 (same)
- **Truth**: holds — code parameters match both datasheets; small drift: the test cites "Table 10" (it holds CRC-annotated conversion values) and calls 0xBEEF→0x92 an "SHT3x" vector, though it is the SGP40 datasheet's own Table 7 example
- **Fit**: refines OR4/OR19.a (2) (independent oracle) · pillar P4
- **Home**: module header → SPECIFICATION.md Part G catalog entry for `crc_checks`

### G3.002 CRC and codec primitives never raise
- **Req**: Every public CRC and framing-codec method returns None/False on invalid input or failed allocation and never raises, except CRC `add()`/`check()`, whose MemoryError is a documented controlled raise; every caller of those two catches MemoryError itself. Pass-through mode (poly None) returns the caller's object unchanged.
- **Class**: product
- **Sources**: ALGO.N002, N006, N007, N009, N043, N081 · stated at `src/crc_checks.py:4-6`, `src/framing_codecs.py:3`, commit `500851c`
- **Provenance**: A — rule text since `b85a056`/`323a1a7`; the controlled-raise wording from `500851c` ("raising is allowed, but only in a documented, controlled manner")
- **Truth**: holds — `asy_uart_driver.py:337-344, 431-432` catch MemoryError around `check()`/`add()`; the FRAM manager's CRC32 path (`asy_fram_manager.py:651, 693`) not traced
- **Fit**: refines OR26 (handled at the right layer) · pillar P2
- **Home**: module headers → Part G catalog

### G3.003 Stateful CRC and codec instances are never shared
- **Req**: Incremental CRC state (`run_inc`/`check_inc`) and a delimited codec's scratch belong to one instance and one sequence; every construction site makes its own instance, and a caller finishes with a returned scratch view before the next `encode_into()`.
- **Class**: code-style
- **Sources**: ALGO.N003, N011, N072, N080 · `src/crc_checks.py:6`, `src/framing_codecs.py:53-55`, BACKLOG.md "Framing_COBS instance shared", commit `32ceee8`
- **Provenance**: A — `32ceee8` ("instance-local by design, not concurrency-safe by accident")
- **Truth**: holds by convention — `asy_uart_driver.py:76` builds its own `CRC_Pass()`; no mechanical guard exists, and a shared instance would fail silently
- **Fit**: extends OR41.a (shared-resource matrix) · pillar P2
- **Home**: module comments → Part G catalog

### G3.005 Framing codecs are pluggable with pass-through default
- **Req**: The UART driver takes a pluggable framing codec with pass-through as default; a delimited codec receives one frame without its delimiter, and the caller's buffer holds the worst-case encoded frame (else None). COBS's 0x00 delimiter cannot collide with a UID rollover.
- **Class**: product

### G3.006 Math helpers return None, never raise
- **Req**: Every `math_helpers` function returns None for a None, out-of-domain or NaN input and for any residual math error (ValueError, ArithmeticError), relying on a domain gate before computation; it does not defend against wrong types, which mypy-checked callers exclude.
- **Class**: product
- **Sources**: ALGO.N014, N019, N021, N023, N025, N027, N046 · `src/math_helpers.py:3`, `:60-61, 82-83, 97-98, 115-116, 135-136`
- **Provenance**: A — rule text since `b85a056`
- **Truth**: holds — gates of the form `not (lo <= x <= hi)` reject NaN; `ZeroDivisionError` is an `ArithmeticError` subclass (`py/objexcept.c:317`), so the catches are complete (and ALGO.N075's reverted explicit catch was redundant)
- **Fit**: restates SPEC D.2; refines OR26 · pillar P2

### G3.013 Fixed-point arithmetic reproduces C int32 semantics
- **Req**: The Q16.16 helpers reproduce the C reference's int32 behaviour exactly — overflow detection, FIX16_MINIMUM/OVERFLOW results and wrap — and no loop in them can run unbounded.
- **Class**: product
- **Sources**: ALGO.N031, N032, N041, N059 · `src/voc_algorithm.py:7, 41-43, 236-247`, `tests/test_voc_algorithm.py:368-381`
- **Provenance**: F — `gia` fixpoint `.c:120-150` (`while (divider < remainder)` on uint32, then `if (!bit) return FIX16_OVERFLOW`)

Feeds the defect scan (ALGO.S01/S06)

### G3.015 VOC sampling and index semantics follow Sensirion

- **Class**: platform
- **Sources**: ALGO.N052, N053, N054, N062, N063, N064, SENS.N172, N179 · `src/asy_sgp40_driver.py:467-476, 645-647`, SPEC A.4 (~247)

### G3.020 Validate before any lossy numeric conversion
- **Req**: A value is range- and NaN-checked before `int()`, `struct.pack()`/`pack_into()` or `to_bytes()`, and before any shared buffer is touched, because `int()` truncates toward zero and MicroPython's pack silently truncates; truncation that remains (TempOffs 0.01 ticks) is stated as the driver's, not the chip's.
- **Class**: product
- **Sources**: BUS.N101, N137, SENS.N087, N140, N215, N216, N217, N310, N314 · SPEC F.1 (~3510), `tests/test_asy_scd30_driver.py:282-364`, SPEC A.4 (~243-245)
