### G5/R09 Timer arm failures degrade, never stall silently
- **Req**: Every `Timer.init()`/`Timer(period=…)` arm site sits in a `try` catching `(OSError, MemoryError)`: rp2's alarm pool holds `PICO_TIME_DEFAULT_ALARM_POOL_MAX_TIMERS` alarms (value read from pico-sdk `98a542c` in A.U0.03's corpus; not in the A-L corpus) and exhaustion raises `OSError(ENOMEM)`; a bare `Timer()` never reaches the pool; a re-arm after `deinit()` may succeed or raise. A failed arm is handled in place and never reboots by itself: the uptime timer runs without uptime, the reboot path falls back to watchdog starvation, a storage pause is aborted rather than left on. The failure is persisted where an async context exists, deferred from Timer context to the woken task otherwise; comments state the consequence accurately.
