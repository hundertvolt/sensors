### G5/R09 Timer arm failures degrade, never stall silently
- **Req**: Every `Timer.init()`/`Timer(period=…)` arm site sits in a `try` catching `(OSError, MemoryError)`: rp2's alarm pool holds 16 alarms (pico-sdk `PICO_TIME_DEFAULT_ALARM_POOL_MAX_TIMERS`) and exhaustion raises `OSError(ENOMEM)`; a bare `Timer()` never reaches the pool; a re-arm after `deinit()` may succeed or raise. A failed arm is handled in place and never reboots by itself: the uptime timer runs without uptime, the reboot path falls back to watchdog starvation, a storage pause is aborted rather than left on. ### G5/R11 Locks: caller-held, fixed order, safe release

### G5/R57 Threat model: trusted home LAN, robust against bad input
- **Req**: The firmware assumes a trusted home LAN. Accepted, documented limitations: unauthenticated REST writes (config, `SystemCmd` reboot/bootloader/mempause, `ResetErrors`), the webserver bound to 0.0.0.0, UDP services that trust their peers' source address, a 16-bit DNS transaction id, the hotspot's default radio security and shared fallback password (R60), information any LAN client can read; browser-borne attacks (DNS rebinding, CSRF, clickjacking), spoofing by a LAN peer and radio-range attackers are out of model.
