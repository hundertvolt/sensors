### G9/R03 SGP40 VOC backup semantics
- **Req**: SGP40 backs up its VOC state to FRAM once per `BackupPeriod` minutes (0 = off) and verifies it about once an hour of backups. At boot it waits up to `WaitTimeNTP` seconds (capped at 600) for NTP before restoring; `WaitTimeNTP = 0` means "never wait": restore once, immediately, never "no restore". A backup older than `BackupMaxAge` minutes is rejected (0 = no age limit; a negative age is rejected, not passed); the age check is skipped when NTP never syncs; an untimestamped backup is written once the wait expires; after every timestamped write the NTP wait re-arms (the owner's `improved-quality/` design); the 45-sample VOC blackout is skipped after a restore; the chunk is not re-read every second while waiting. Every "0 means" lives in the schema (C.5 special values) and DEVICE_REFERENCE.md, not only in `@web` text.

## 6 Gaps

- **Commissioning and operator actions in one place** (P1, P3). The firmware needs a person for a few one-time steps: joining the hotspot to set Wi-Fi, the first `AmbPres` PUT that starts SCD30 continuous measurement (OR71.a (2)), the manual `ForceCalRef` procedure (A14), ISL29125 calibration (A38), reading `reset_reason` (OR60.a), the reflash runbook (OR52.a (1), OR59.a). No requirement gathers them. Proposed: DEVICE_REFERENCE.md carries one commissioning and operating section listing every operator action with its trigger; the runbook links to it.
- **A defined release point** (process, P12). OR52.a (2) freezes keys "from the release on" with "a golden stored-config fixture from the release"; OR58.a harmonizes keys "before the release". Nothing defines the release: no version rule (L67: version bump by hand), no tag, no release note. Proposed: the merge into `main` is tagged with the `buildgen/version.py` version; a short release note lists user-visible changes versus legacy (renamed keys, `reset_reason`, overnight window, compare-before-write); the golden fixture is taken from that tag.
- **Tag form for decisions reviewed after OR2.c** (P7). OR2.c logs decisions on the owner's behalf for review; OR68.a (4) rule 2 keeps an accepted agent recommendation labelled the agent's. The permanent tag after review is undefined. Proposed: "(agent, date; owner-reviewed, date)", or the owner's words and "(owner, date)" when the owner rules differently.
- **One normative REST API reference** (P12). OR58.a makes the new API "the only reference" and OR52.a (2) freezes it at release, but its routes, keys, types, units and ranges are spread over SPEC A.8, C.5, H and the `@web` tags. Proposed: one generated reference (from schemas and `@web` tags) that the mock server, website tests and golden fixture are checked against; lead to check against G6/G7's HR161/HR170 first.
