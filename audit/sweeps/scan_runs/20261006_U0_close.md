## 3. Findings

### SF-U0-01 Archive-ancestry notice is invisible in CI

- **Site**: `tests_scripts/test_citations.py:158-165` (`_archive_state()`), `:88-93` (`_datasheets_checked()`, dead
  today); `scripts/test.sh:265` (`uv run pytest tests_scripts -q`); `.github/workflows/ci.yml:432` (checkout, no
  `fetch-depth`).
- **Class / mode**: 4 and 7; CI vs local (shallow clone).
- **Failure**: in every CI run `git merge-base --is-ancestor 12640c2 HEAD` fails (commit object absent), `git rev-parse
  --is-shallow-repository` says `true`, so archive citations are skipped and the notice goes to `print()`.
- **Layer below**: `actions/checkout` defaults to `fetch-depth: 1`; pytest captures stdout per test and shows it only
  for a failing test (`-q` with the default `-r fE` shows neither passes' output nor a summary of it).
- **Our code**: prints the notice; the test passes; nothing reaches the log.
- **Effect**: the check M.TSC.063 (e) describes ("skipped with a notice in a shallow clone") never runs in CI and the
  notice the work order relies on is never seen; only a local full clone checks ancestry. All devices: none (host
  tooling).
- **Minimal fix**: `warnings.warn(...)` instead of `print()` in both functions (pytest prints a warnings summary by
  default, also under `-q`); no `fetch-depth` change needed.
- **Owner**: U0 now (A.U0.08, M.TSC.063 U0 stage).

### SF-U0-02 A file the scanner cannot read counts as having no prose

- **Site**: (a) `tests_scripts/_repo_scan.py:69-77` (`read_text()` returns `None` on `UnicodeDecodeError`), consumed at
  `test_citations.py:202` and `test_decision_vocabulary.py:75`; (b) `_repo_scan.py:207-219` (`prose_blocks()` returns
  `[]` for an unlisted suffix).
- **Class / mode**: 4; a file that cannot be decoded, a new file type.
- **Failure**: a tracked Markdown, comment or config file with one non-UTF-8 byte, or of a suffix not in the four
  tables (e.g. a future `.pyi`, `.c`, `.jsonc`, an extension-less script), drops out of both checks with no trace.
- **Layer below**: `bytes.decode("utf-8")` raises; `Path.suffix` returns what is there. Nothing below hides anything.
- **Our code**: maps both to "no prose" (`None` / `[]`), the same answer as a JSON file that genuinely has none.
  `test_import_placement.py:309` reads with `read_text(encoding="utf-8")` and fails loudly: the three checks disagree.
- **Effect**: none today (measured: every in-scope file decodes; the 11 extractor-less files have no comments); a later
  file escapes rule 1 and rule 5 silently.
- **Minimal fix**: (a) `read_text()` returns `None` only for a NUL-bearing (binary) file and lets `UnicodeDecodeError`
  raise, as import placement does; (b) one test asserting every scanned text file's suffix is either read by
  `prose_blocks()` or in an explicit no-prose set (`.json`, `.nvmrc`, `LICENSE`).
- **Owner**: U0 now (A.U0.08/A.U0.09: `_repo_scan.py` lands in U0).

## 4. Microdot v2.6.2 → v2.7.0 (no finding)

The whole diff (38 lines) is: five `str.format` → f-string rewrites (`set_cookie`, `send_file`'s `Cache-Control`,
`URLPattern.register_type`, the `re:` segment, two `__repr__`), a new `Microdot.query()` decorator, and a `Vary` merge
at the end of `dispatch_request()` (`:1581-1588`).

- f-strings: enabled on rp2 (`ports/rp2/mpconfigport.h:81` EXTRA_FEATURES → `py/mpconfig.h:1335`), in the Unix
  standard variant (`ports/unix/variants/standard/mpconfigvariant.h:28`) and in `mpy-cross` (`mpy-cross/mpconfigport.h:81`).
  The lexer stops an expression only at `:`/`}` outside brackets (`py/lexer.c:421-436`), so `{type_[3:]}` keeps its
  slice; none of the five ends in `=` (the debug form, `:441`). A lexing failure would be a compile error, never silent.
  Of the five, our code reaches only `send_file()` (`src/asy_webserver_service.py:664`), whose f-string line runs only
  with a non-`None` `max_age`, which we never pass.
- `query()` registers nothing unless called; we do not call it. A `QUERY` request still meets our GET/PUT routes'
  method check exactly as before.
- `Vary`: runs only when `req.g._vary` exists; nothing in `src/`, `digital_twin/` or `ext/microdot.py` sets it.
- Unchanged error paths our code relies on (read at both tags): `dispatch_request()`'s exception walk and 500 fallback
  (`:1540-1565`), `print_exception` (SF-M4-01's rebinding target, now `:1536`), `Response.write()`'s muted
  `ECONNRESET`/`EPIPE` (SF-M2-05), the body cap ordering Part I.6 cites (`:1418/:1428/:1461`, checked against HEAD).
- Pin: `ext/microdot.py` and the stubs have no hash test yet; a hand edit before M.TSC.154 (`test_vendored_microdot.py`,
  A.U19.18/A.U34.12) is caught by review only. Pre-existing (v2.6.2 had none either); covered by the plan, not new.
